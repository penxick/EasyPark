# EasyPark Mobile

Flutter/Dart, Android 7.0+ (API 24) и подготовка iOS. Выполнен этап 9 — информация о парковке.

- `lib/app.dart` — приложение с MaterialApp.router.
- `lib/core/` — токены Figma, тема, UI-kit, маршруты, API-клиент и состояния загрузки.
- `lib/ui_kit_preview.dart` — отдельный каталог компонентов без сервера.
- `lib/features/auth/` — Splash, формы Login/Register, AuthRepository и AuthController.
- `lib/core/storage/token_storage.dart` — хранение JWT через Android KeyStore / iOS Keychain.
- `test/` — API, loading state и widget-тесты маршрутизации.
- `tool/api_smoke.dart` — проверка реального backend.

Команды запуска: [корневой README](../README.md).
Настройки сети, scope и список изменений: [отчёт этапа 2](../docs/stage-2.md).
Приложение проверяет сохранённую сессию через `/users/me`, при необходимости
показывает вход. Доступны регистрация и вход. После успеха открывается заглушка
карты с нижней навигацией: Карта, Бронирования, Профиль. Разделы сохраняют состояние при переключении. Данные и действия разделов реализуются на следующих этапах.
Ошибки сети при восстановлении не удаляют JWT. Android backup отключён.
API_BASE_URL задаётся как на этапе 2; для Android Emulator — `http://10.0.2.2:3000/api/`.

Проверка на эмуляторе с работающим backend и отдельным временным email:

```powershell
flutter test integration_test/auth_flow_test.dart -d emulator-5554 --no-enable-impeller --dart-define=TEST_EMAIL=stage5-your-unique-id@example.com --timeout=3m
```

Тест создаёт аккаунт в backend и оставляет JWT для проверки перезапуска процесса.
Используйте только тестовый эмулятор; после проверки удалите только созданный аккаунт.
Контракт и результаты: [отчёт этапа 5](../docs/stage-5.md).

Каталог: `flutter run -t lib/ui_kit_preview.dart`.
Импорт компонентов: `package:easypark/core/widgets/ui_kit.dart`.
Описание API компонентов и адаптации: [отчёт этапа 3](../docs/stage-3.md).

Визуальная проверка без эмулятора (путь к установленному Flutter SDK):

```powershell
flutter test tool/render_ui_kit_test.dart --dart-define=FLUTTER_SDK=C:/Users/User/flutter/flutter --timeout=45s
```

Результат: шесть PNG в `../.artifacts/`, ширина 390 px и 320 px с текстом 200%.
Это ручная проверка рендера, не сравнение с утверждёнными golden-изображениями.


## Карта — этап 8

`lib/features/map/` содержит модель Parking, ParkingRepository, MapScreen,
ParkingMap и ParkingSummary. API использует текущий JWT; тайлы OpenStreetMap
загружаются отдельно, без JWT. Ключ карты и разрешение геолокации не нужны.
Для реального фона карты требуется интернет. Ссылка атрибуции открывается браузером.
Число мест доступно в подробном экране; «Подробнее» загружает его через GET /parkings/:id.

Проверка карты на тестовом Android-эмуляторе (backend должен работать, seed выполнен):

```powershell
$testEmail = 'stage8-' + [guid]::NewGuid().ToString('N') + '@example.com'
flutter test integration_test/map_flow_test.dart -d emulator-5554 --no-enable-impeller --dart-define=TEST_EMAIL=$testEmail --timeout=3m
```

Тест создаёт временного пользователя; после проверки удалите только эту запись.
Диагностический флаг рендера нужен этому эмулятору и не включён в настройки приложения.
[Файлы, результаты и ограничения этапа 8](../docs/stage-8.md).

## Информация о парковке — этап 9

Экран загружает актуальные данные по ID, показывает адрес, тариф, режим работы,
описание и поля счётчиков мест. Пока API не возвращает счётчики, отображается
«Нет данных». Есть обновление, повтор при ошибке и возврат на карту.
Текущий Android-интеграционный тест map_flow_test.dart также проверяет переход
из карты в подробности и обратно. Полный список файлов: [этап 9](../docs/stage-9.md).

После этапа 10 backend возвращает freeSpaces/totalSpaces, вычисленные по местам.
Подробный экран автоматически показывает эти значения. Краткая карточка карты
и Flutter-схема мест на этапе 10 не изменялись.

## Схема парковки — этап 11

«Выбрать место» открывает `/parking/:id/spaces`. Экран загружает места через
JWT API, показывает коды и статусы, поддерживает масштабирование и перемещение.
Выделяется только свободное и физически незанятое место. Это локальный выбор,
без создания бронирования. Есть обновление, пустое состояние и повтор запроса.
Android-тест `map_flow_test.dart` теперь проверяет также схему и возврат из неё.
[Полный список файлов и проверки](../docs/stage-11.md).

## Бронирование — этап 13

Кнопка «Забронировать» после выбора места открывает `/parking/:id/book/:spaceId`.
Данные места и тариф повторно загружаются, доступны длительности из ТЗ.
Создание и отмена используют JWT API этапа 12. Активные брони восстанавливаются
из сервера во вкладке «Бронирования»; категории истории пока не добавлены.
При неопределённом результате POST кнопка проверки сначала читает список броней,
чтобы не отправлять повторное создание вслепую.

`integration_test/reservation_flow_test.dart` требует работающий backend и отдельное
свободное тестовое место T01 с тарифом 120,51 ₽/час. Передайте `TEST_EMAIL`
(`stage13-<32 hex>@example.com`), `TEST_PARKING` и `TEST_SPACE` через dart-define.
После теста удалите только созданные тестовые записи; не используйте реальные места.
[Файлы, результаты и границы этапа](../docs/stage-13.md).

## История — этап 14

Экран бронирований загружает весь личный список и разделяет его на активные,
завершённые и отменённые. Категория сохраняется при обновлении; отменённая
карточка сразу переходит в свою категорию. История восстанавливается из API.
`reservation_flow_test.dart` теперь проверяет также отменённую категорию и её
обновление. [Полный отчёт](../docs/stage-14.md).

## Профиль — этап 15

Экран показывает актуальные данные `GET /users/me`: имя, email, дату регистрации.
Выход удаляет токен из защищённого хранилища и закрывает доступ к основным экранам.
Проверка Android: `integration_test/profile_flow_test.dart` с `TEST_EMAIL`
формата `stage15-<32 hex>@example.com`. Тест регистрирует временного пользователя,
проверяет профиль, выход, отсутствие сохранённой сессии и повторный вход.
После проверки удалите только этот аккаунт. [Подробный отчёт](../docs/stage-15.md).
