# Этап 17 — Vehicle Library

Создана конфигурация поддерживаемых классов транспорта. Этап 18 не начат.

## Поведение

`cv-service/app/vehicle_classes.json` содержит 11 классов из примера ТЗ:
car, SUV, crossover, pickup, van, minivan, truck, bus, minibus, motorcycle, scooter.
Чтобы изменить список, нужно отредактировать JSON и пересобрать контейнер CV.
Конфигурация включается в образ существующей командой COPY app и читается при старте.

Детектор сопоставляет названия с метками модели, игнорируя регистр и крайние пробелы.
Числовые ID берутся из модели; в ответе используется написание из конфигурации.
Подклассы не угадываются, отсутствующие классы пропускаются. С текущей YOLO11n
пересечение составляет car, motorcycle, bus, truck.

Исправлено поведение при полном отсутствии совпадающих классов: вместо отказа
инициализации сервис загружает и прогревает модель, остаётся ready и возвращает
`{"vehicles":[]}` для корректных изображений. Для таких запросов повторный inference
не запускается. Проверки формата, содержимого и размера изображения сохраняются.
Пустой конфигурационный список также допустим.

Ошибки самой конфигурации (невалидный JSON, неправильный тип данных, пустые
названия или дубликаты без учёта регистра) приводят к безопасному 503 readiness
через существующую обработку ошибок инициализации. Они не смешиваются с допустимым
отсутствием классов у конкретной модели.

## Все созданные файлы

- `cv-service/app/vehicle_classes.json` — редактируемый список классов.
- `cv-service/app/vehicle_library.py` — загрузка, валидация и сопоставление с метками модели.
- `cv-service/tests/test_vehicle_library.py` — восемь тестовых случаев библиотеки и совместимости.
- `docs/stage-17.md` — этот отчёт.

## Все изменённые файлы

- `cv-service/app/detector.py` — применение конфигурации вместо фиксированного набора четырёх классов; безопасная обработка пустого пересечения.
- `cv-service/tests/test_detect.py` — адаптация теста обработки bbox к сопоставлению классов.
- `cv-service/README.md` — инструкции изменения конфигурации, поведение и границы этапа.
- `README.md` — текущий этап и ссылка на отчёт.

Зависимости, Dockerfile, backend и mobile не изменены. Обучение и интеграция с
Flutter не выполнялись. Пользовательский инструмент этапа 18 не создавался.
