# Исправление проверки подключения — 1.2.1+4

Проверка строит корневой URL через baseUri.resolve('/'), затем запрашивает health отдельным клиентом без JWT. API_BASE_URL с /api/ и /api сохраняет нормализованный /api/ для рабочих запросов. Префикс не добавляется повторно.

Успех — только HTTP 200 и JSON status=ok, service=easypark-backend. Остальные статусы, включая 404 и другие 2xx, отклоняются. Сохранение и выход из старой сессии выполняются только после успешной проверки.

В исходном коде использовался переход на родительский путь ../, который уже работал для ровно /api/, но зависел от глубины пути. Теперь корень задан явно, а статус проверяется строго.

Изменения этого исправления:
- mobile/lib/features/auth/server_settings_screen.dart — корневой URL health, строгая проверка, внедрение тестового клиента.
- mobile/lib/core/api/api_client.dart — необязательный expectedStatusCode; существующие вызовы сохраняют прежнее поведение.
- mobile/test/server_settings_test.dart — 12 новых проверок: варианты URL, ошибочные статусы/JSON, сохранение токена и адреса, неизменность API-префикса.
- mobile/pubspec.yaml — 1.2.1+4.

Flutter analyze: без замечаний. 34 целевых теста прошли (настройки сервера, ApiClient, авторизация, сессии). git diff --check: без ошибок. Backend, Docker, PostgreSQL, GPS, маршрутизация и логика бронирования в этом исправлении не изменялись.

Проверки HTTP выполнены тестовым транспортом. Реальный Cloudflare-туннель и установка на устройство в этой проверке не тестировались. APK использует http://10.0.2.2:3000/api/ по умолчанию; адрес меняется через настройки.
