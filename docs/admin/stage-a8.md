# A8 — Управление парковками Flutter

Дата: 10 октября 2026 года.

## Возможности

Раздел ADMIN «Парковки» теперь показывает общий список из GET /api/parkings:
название, адрес, стоимость за час, количество мест, свободные места и режим работы.
Доступны просмотр, создание, редактирование и удаление. Карточка показывает
описание и координаты. Для чтения используются существующие Parking,
ParkingDetails и ParkingRepository; изменения отправляются в готовый Admin API A3.
Новых таблиц, endpoints и зависимостей нет.

Форма содержит семь полей ТЗ. Проверяются обязательность, длины, конечные числа,
диапазоны latitude/longitude, неотрицательная цена и два десятичных знака.
Десятичная запятая принимается. Нулевая стоимость допустима. Данные формы
сохраняются при ошибке; во время запроса поля и кнопка сохранения отключены.
После сохранения открывается обновлённая карточка, список при возврате загружается
заново. После удаления список обновляется без перезапуска приложения.

Удаление требует отдельного подтверждения с текстом из ТЗ. Кнопка красная и
отделена от остальных действий. HTTP 409 показывает сообщение о связанных
данных/конкурентном изменении; решение о безопасном удалении принимает backend.
Raw stack trace не показывается. Есть loading, empty, error/retry, ручное
обновление и pull-to-refresh для просмотра. ADMIN routes защищены прежним guard;
при 403 выполняется повторная проверка роли.

Использованы локальные Figma OperatorApp/ParkingList/ParkingMonitor и общий UI-kit:
белые карточки, серый фон, отступы, типографика и кнопки. Готовой формы CRUD в этих
референсах нет; форма составлена из существующих Flutter-компонентов. Web-код
и web-зависимости не переносились.

Координаты на A8 вводятся численно. Выбор точки и административная карта относятся
к A9. Кнопка «Управлять местами» ведёт на защищённую заглушку A10. Эти этапы
не начинались. Общий USER API читает те же данные; пользовательская карта
получит изменения при открытии/обновлении.

## Проверки

- Flutter analyze: без замечаний.
- Полный Flutter suite: 94 теста прошли, включая 6 новых A8.
- Проверены список/детали/редактирование с обновлением, обязательные поля,
  координаты, нулевая цена, подтверждение/отмена удаления, HTTP 409,
  сохранение ввода после HTTP 500, блокировка повторного сохранения,
  повтор загрузки и адаптивность 320 × 640 с масштабом текста 2.
- Android integration test на emulator-5554 с реальным HTTP API прошёл:
  ADMIN login → создание → редактирование → чтение изменённого адреса через
  общий GET /parkings → отмена удаления → подтверждение удаления → проверка
  отсутствия записи через общий API → logout.
- Тестовая парковка удалена самим сценарием; дополнительно проверено её отсутствие
  в PostgreSQL. Временный ADMIN и файлы с тестовыми credentials удалены.
  Системный пароль во Flutter не встраивался.
- Android debug APK собран после тестового запуска для обычного приложения,
  установлен и запущен на emulator-5554 (API_BASE_URL=http://10.0.2.2:3000/api/).
- Снимки списка, карточки и формы просмотрены; сохранены локально в
  .artifacts/admin-a8/. Снимок формы сделан с фокусом на нижнем поле; доступность
  кнопки создания дополнительно подтверждена успешным UI-сценарием.
- Все 75 SHA-256 ТЗ/Figma совпали; git diff --check прошёл.

Первый анализ выявил замечания к фигурным скобкам — исправлены. Промежуточные
widget-тесты выявили гонку фокуса/прокрутки в тестовом сценарии; перед нажатием
кнопок добавлено снятие фокуса и ожидание завершения layout. Итоговый полный
прогон прошёл. Backend/CV исходники не менялись; их полная повторная проверка
на этом этапе не выполнялась. Проверка iOS не выполнялась.
