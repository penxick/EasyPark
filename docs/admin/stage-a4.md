# A4 — ParkingSpace Admin Backend

Дата: 8 октября 2026 года. Этап завершён; A5 не начат.

## API и данные

Используются существующие ParkingSpace, ParkingSpacesService и таблица
parking_spaces. Новые таблицы, миграции и зависимости не требуются.

| Метод  | Путь                                  | Результат              |
| ------ | ------------------------------------- | ---------------------- |
| POST   | /api/admin/parkings/:parkingId/spaces | 201, созданное место   |
| PATCH  | /api/admin/spaces/:id                 | 200, обновлённое место |
| DELETE | /api/admin/spaces/:id                 | 204 без тела           |

На всех операциях JwtAuthGuard → RoleGuard: без JWT — 401, USER — 403.
Некорректный положительный integer ID — 400, отсутствующий объект — 404.

POST принимает обязательные code, x, y, polygon; parkingId берётся из маршрута.
Code обрезается по краям, не пустой, до 20 символов; уникальность сохраняется
в рамках парковки с существующей чувствительностью к регистру. x/y — конечные
числа >= 0. Polygon — null или 3–1000 пар конечных чисел. Null означает отсутствие
разметки; координаты polygon не преобразуются в географические или экранные.
Начальное состояние — FREE, physicalOccupied=false, hasActiveReservation=false.

PATCH принимает непустое подмножество code, x, y, polygon и available (boolean).
Пропущенные поля сохраняются, polygon:null явно очищает разметку. Другие null,
числа в виде строк, неверные типы, неизвестные поля отклоняются. Нельзя передать
status, physicalOccupied, parkingId или id для произвольной перезаписи данных.

Чтение остаётся общим: `GET /api/parkings/:parkingId/spaces`. Ответ дополнен
hasActiveReservation, рассчитанным на backend: существует ACTIVE/PENDING с
endTime в будущем. Персональные данные брони не возвращаются. Статус RESERVED
сам по себе не доказывает наличие брони (это важно для существующих демоданных).
До прохода worker у истёкшей брони статус места может оставаться RESERVED, но
hasActiveReservation уже false; изменение доступности завершает такую бронь сразу.

## Доступность, история и конкуренция

- available:false переводит место в UNAVAILABLE и не отменяет действующую бронь.
- available:true восстанавливает RESERVED при действующей брони, иначе OCCUPIED
  при physicalOccupied=true, иначе FREE.
- Код, геометрия и доступность не изменяют physicalOccupied. При пропущенном
  polygon сохраняется существующая разметка, необходимая для CV.
- Для обработки истёкших бронирований переиспользован прежний метод сервиса
  Reservation, теперь доступный как expireLockedSpace. Его логика не дублировалась.
- Изменение и удаление блокируют строку места в транзакции, как существующие
  бронирование/отмена/expiry. Создание также блокирует родительскую парковку для
  согласования с её удалением. Уникальность защищена индексом PostgreSQL.
- Любая история Reservation запрещает удаление: 409 SPACE_HAS_RESERVATIONS.
  Удаляется только место без истории; каскадное удаление бронирований не добавлено.
- Дубликат кода — 409 SPACE_CODE_EXISTS; FK-конфликт — SPACE_HAS_RELATED_DATA;
  deadlock/таймаут блокировки — SPACE_BUSY с предложением повторить запрос.

USER не может забронировать UNAVAILABLE благодаря существующей проверке сервиса
бронирования. Отмена брони не снимает административное отключение места.
Диалог подтверждения удаления будет реализован вместе с Flutter UI в A10.

## Проверки

- Nest build, ESLint и Prettier прошли.
- 61 backend-тест прошёл: 12 базовых, 49 интеграционных; пропусков нет.
- Проверены JWT/роль для каждой операции, DTO/геометрия, null/неизвестные поля,
  уникальность кода и конкурентное создание, откат конфликтующего изменения,
  доступность и сохранение физической занятости/разметки.
- Проверены активная бронь при отключении/включении, отмена при отключённом месте,
  завершение истёкших ACTIVE/PENDING, удаление при всех пяти статусах брони,
  одновременное бронирование с отключением и удалением.
- Прошли прежние проверки A2/A3, регистрации, JWT, парковок и бронирований.
- 79 Flutter-тестов прошли. Добавлена проверка совместимости пользовательской
  модели с hasActiveReservation; производственный Flutter-код не менялся.
- Docker backend пересобран и healthy. Через работающий HTTP API проверены
  создание места → отключение → включение/редактирование → общее чтение → удаление.
  Временная проверочная парковка удалена. PostgreSQL и прежний CV-service healthy.

При возобновлении Docker Desktop был выключен: начальные интеграционные проверки
получили ECONNREFUSED. Также тесты были запущены до завершения пересборки dist,
что вызвало MODULE_NOT_FOUND. После запуска PostgreSQL и завершения сборки полный
набор прошёл. Замечание Prettier исправлено. Ненужная пересборка неизменённого CV
остановлена; сервис запущен из существующего образа. В Flutter-тестах остаются
диагностические сообщения искусственно повреждённых map tiles и уведомление OSM;
все проверки завершились успешно. Нерешённых ошибок A4 не обнаружено.
