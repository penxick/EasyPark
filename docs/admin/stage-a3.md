# A3 — Parking Admin Backend

Дата: 7 октября 2026 года. Реализованы административные изменения парковок.
Следующий этап — A4, управление ParkingSpace на backend.

## API

Все административные операции используют JwtAuthGuard → RoleGuard:
без JWT возвращается 401, для USER — 403, для ADMIN доступ разрешён.

| Метод  | Путь                    | Результат                                        |
| ------ | ----------------------- | ------------------------------------------------ |
| POST   | /api/admin/parkings     | 201, созданная парковка с totalSpaces/freeSpaces |
| PATCH  | /api/admin/parkings/:id | 200, обновлённая парковка с количеством мест     |
| DELETE | /api/admin/parkings/:id | 204, без тела                                    |

Для чтения используются прежние `GET /api/parkings` и
`GET /api/parkings/:id`. Отдельные административные копии чтения не создавались.
ADMIN и USER работают с общей таблицей parkings, через существующий ParkingService.

POST принимает name, description, address, latitude, longitude, pricePerHour,
workingHours. Все поля обязательны. Строки обрезаются по краям и не могут быть
пустыми: name/workingHours до 200, address до 500, description до 10000 символов.
Координаты — числа в диапазонах [-90,90] и [-180,180]; хранение сохраняет
существующую точность БД до 6 знаков. Цена — число от 0 до 99999999.99, максимум
два десятичных знака. Строки вместо чисел, null и неизвестные поля отклоняются.

PATCH принимает непустое подмножество тех же полей. Пропущенные значения остаются
прежними. Частичный SQL UPDATE не перезаписывает параллельные изменения других
полей. Идентификатор — положительный integer до 2147483647; неверный ID — 400,
несуществующая парковка — 404. Изменения цены не пересчитывают сохранённую
стоимость прежних бронирований.

## Безопасное удаление

Транзакция блокирует парковку, затем её места в порядке ID. Блокировка родителя
не позволяет вставить новое место через FK во время удаления. Бронирование
использует существующую блокировку места: удаление ждёт завершения операции,
затем проверяет историю в новом READ COMMITTED snapshot.

Если есть хотя бы одна Reservation любого статуса, возвращается 409 с кодом
`PARKING_HAS_RESERVATIONS` и понятным сообщением. Парковка, все места и история
сохраняются. Если истории нет, места и парковка удаляются в одной транзакции.
FK-конфликт даёт 409 `PARKING_HAS_RELATED_DATA`; deadlock/таймаут блокировки —
409 `PARKING_BUSY` с предложением повторить запрос. CASCADE для истории не добавлен.

Подтверждение удаления во Flutter относится к A8; UI в A3 не изменялся.
ParkingSpace CRUD пока не реализован и остаётся задачей A4.

## Проверки

- Nest build, ESLint и Prettier прошли.
- Все 52 backend-теста прошли, без пропусков: 12 базовых и 40 интеграционных.
- Проверены 401/403 на каждой административной операции, создание и чтение USER,
  все поля формы, границы координат, нулевая цена, запрещённые поля и типы,
  пустой PATCH, неизвестные ID, одновременное изменение разных полей.
- Удаление проверено для пустой парковки, парковки с местами без истории и
  парковки с Reservation каждого из пяти статусов. Проверен откат с сохранением
  всех мест и неизменность цены ранее созданной брони.
- Проверена гонка бронирования и удаления: успешная бронь сохраняет парковку и
  историю, успешное удаление не допускает создания брони на удалённое место.
- Прежние проверки ADMIN auth, USER auth, парковок, мест и бронирований прошли.
- Docker backend пересобран и healthy. В запущенном контейнере проверены
  POST → PATCH → общий GET → DELETE → GET 404; временная парковка удалена.
  PostgreSQL и CV-service также healthy.
- Все 75 контрольных сумм защищённых исходных материалов совпали.

Первая Docker-сборка прервалась из-за TLS timeout Docker Hub. Повторная сборка
прошла без изменения зависимостей. Замечание Prettier к тестовому файлу исправлено,
повторная проверка форматирования прошла. Нерешённых ошибок A3 не осталось.

Новая миграция не нужна. Исходники Flutter, CV-service, ТЗ и Figma не менялись.
Проверки используют временные записи и удаляют только собственные тестовые данные.
