# A9 — Добавление и перенос парковки через карту

Дата: 10 октября 2026 года.

## Реализация

В ADMIN → Парковки добавлена кнопка «Открыть карту». Карта отображает существующие
парковки из общего API. «Добавить парковку» включает режим выбора точки; нажатие
показывает выбранный маркер и координаты. «Продолжить» открывает форму A8 с
latitude/longitude. После POST форма закрывается, данные карты запрашиваются
повторно, появляется новый маркер, камера направляется к нему.

Нажатие на существующий маркер открывает редактирование. В форме есть
«Выбрать положение на карте»: выбор возвращает новые координаты, сохраняя
остальные введённые поля. Отмена и системная кнопка «Назад» оставляют черновик
без изменения координат. После PATCH обновляется положение маркера.
Изменение точки до сохранения формы не отправляет запрос в БД.

Переиспользован ParkingMap USER-приложения, flutter_map и OpenStreetMap,
включая attribution, retry фоновых плиток, fit-to-bounds и маркеры. Дополнительные
параметры выбора необязательны и не меняют USER-сценарий. Пустой список парковок
теперь допускается компонентом карты: исходный центр — Красноярск, а не фиктивная
парковка или местоположение пользователя. Долгота нажатия нормализуется в
[-180,180); координаты формы сохраняются с шестью десятичными знаками.

Новые пути /admin/parkings/map и /admin/parkings/pick-location защищены существующим
role guard Flutter; сохранение использует защищённый backend A3. Административная
форма и карта используют те же Parking/таблицы/API, что USER. Новых зависимостей,
миграций и backend-методов нет. UI построен на прежних компонентах и теме;
географическая карта соответствует существующей реализации EasyPark, как требует ТЗ.
Figma-reference не изменялся, схема парковочных мест из него не подменяет карту.

## Проверки кода

- flutter analyze: без замечаний.
- Полный flutter test: 97 тестов прошли, включая прежнюю карту USER и CRUD A8.
- Три новых widget-сценария: пустая карта → выбор → форма → POST → маркер;
  редактирование → отмена/системный возврат → повторный выбор → PATCH → новая
  позиция; ошибка API → retry и экран 320 × 640 с масштабом текста 2.
- USER deep-link тест дополнен обоими новыми маршрутами.
- dart format: 88 файлов, 0 изменений. git diff --check прошёл.
- Все 75 контрольных сумм исходных ТЗ/Figma совпали.

В тестировании найдено переполнение сообщения ошибки при крупном тексте;
исправлено прокруткой блока. Проверка системного возврата опирается на видимый
экран формы: URL provider GoRouter для imperative push может сохранять базовый
путь карты. Тест проверяет сохранность реального черновика, а не этот URL.

## Android-проверка

На emulator-5554 с реальным backend прошёл сценарий ADMIN login → карта → выбор
точки → создание → новый маркер → выбор другой точки → сохранение → USER login
через общий экран входа → проверка совпадения новых координат в USER ParkingMap.
Тестовая парковка удалена, отсутствие записи дополнительно проверено в PostgreSQL.
Временные ADMIN/USER и файлы credentials удалены. Системный пароль не использовался
в тестовой APK. Все изменения данных касались только временной тестовой парковки.

После integration test обычная debug APK повторно собрана, установлена и запущена
на эмуляторе. API_BASE_URL=http://10.0.2.2:3000/api/. Сборка и установка завершились
успешно. Этап A9 завершён; следующий — A10.

Просмотрены снимки .artifacts/admin-a9/a9-pick.png и a9-created.png. На первом
видны реальные OSM-плитки, выбранная точка и координаты. На втором новый маркер
уже отображается, фон в момент снимка ещё серый: загрузка внешних OSM-плиток
асинхронная и не является частью ответа API. Сохранение и положение маркера
подтверждены независимо от фоновых изображений.
