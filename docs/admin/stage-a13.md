## Сквозной Android-сценарий

Новый тест admin_full_flow_test.dart выполнялся на Pixel_7 / emulator-5554,
с настоящими NestJS, PostgreSQL, SecureTokenStorage и картой приложения.
HTTP mock в этом сценарии не используется.

1. Вход временного ADMIN через существующую форму; открытие Dashboard.
2. Выбор точки на карте, заполнение формы, создание парковки, новый маркер.
3. Создание места, отключение и возвращение в эксплуатацию (FREE/UNAVAILABLE).
4. Выход, регистрация USER, появление созданной парковки на пользовательской карте.
5. Восстановление сессии из хранилища; запрет маршрута /admin/analytics и API 403.
6. Выбор места на схеме, создание 30-минутной брони через UI, подтверждение.
7. Повторный вход ADMIN, просмотр брони и карточки USER с историей и счётчиками.
8. Открытие реальной аналитики; проверка наличия активной брони в API.
9. Отображение активной брони у места, отказ удаления места с историей.
10. Вход USER, отмена брони через UI, категория «Отменённые», профиль, выход.

Скриншот аналитики сохранён в .artifacts/admin-a13/a13-analytics.png и просмотрен:
верхняя часть экрана с реальными показателями читаема, обрезаний текста нет.
Это не полное попиксельное сравнение всех экранов с Figma.

Временный ADMIN создавался с случайным паролем. Исходный системный пароль
не встраивался в тестовую APK. После прогона тестовые аккаунты, парковка,
места и бронирования удалены по ограниченной области fixture; файл с временными
данными удалён. Обычная APK пересобрана без test target и тестовых dart-defines.

## Покрытие backend и безопасности

Повторно проверены: регистрация и вход USER; нормализация логина; резервирование
admin; отклонение role при регистрации; JWT 401; USER 403 для ADMIN API;
немедленное применение отзыва роли; отсутствие passwordHash в ответах;
хеширование и идемпотентный bootstrap ADMIN.

Проверены CRUD парковок/мест, видимость изменений USER, изменение координат,
валидаторы, уникальность кода, защита истории и внешних ключей, конкурентные
бронирования/удаление/отключение. Отдельно проверены физическая занятость,
запрет брони недоступного места, отмена, истечение броней и сохранение CV-полей.
Реальные SQL-агрегаты проверены на пустых данных, разных статусах, нескольких
бронях одного места и изменении данных. Users/Reservations API проверены
на пагинацию, категории, карточки и изоляцию пользовательской истории.

## Найденные проблемы и ограничения

- Первый Node-прогон заблокирован sandbox (spawn EPERM); повтор с разрешениями
  успешно выполнил все 76 тестов.
- В локальной Python .venv нет Pillow/Ultralytics. CV проверен штатным Docker
  test image с текущими app/tests, подключёнными только для чтения. Все 30 прошли.
  Осталось предупреждение Starlette о будущем переходе тестового клиента на httpx2.
- Flutter drive задержался на pub get; использован --no-pub с установленными
  зависимостями. После паузы потребовались unpause контейнеров и запуск эмулятора.
- Автоматическая проверка разрешений временно не работала из-за лимита аккаунта;
  после команды продолжить разрешения получены, очистка и проверки завершены.
- Исправлена синхронизация нового Android-теста: дождаться перехода после logout
  перед register, а также завершения сетевой загрузки карты. Первые неудачные
  прогоны не засчитывались; последний полный прогон успешен.
- Ошибок рабочей реализации, требующих правки в этом прогоне, не обнаружено.
- iOS, физический телефон, Windows desktop-сборка, реальная камера и оценка
  точности CV на новых парковках не проверялись. CV-проверки относятся к сервису,
  модели и тестовым изображениям, не к реальной видеосистеме.
- A13 Android-сценарий не заменяет все отдельные CRUD/UI тесты: редактирование,
  успешное удаление и пагинация покрыты существующими backend/widget-тестами.

## Воспроизведение

При работающем Docker и Pixel_7:

1. Из backend: `node test/android-a13-fixture.cjs prepare`.
2. Из mobile: `flutter drive --no-pub --driver=test_driver/admin_base_driver.dart --target=integration_test/admin_full_flow_test.dart -d emulator-5554 --dart-define=API_BASE_URL=http://10.0.2.2:3000/api/ --dart-define-from-file=../.artifacts/a13-fixture.json`.
3. Даже после неуспеха из backend: `node test/android-a13-fixture.cjs cleanup`.
4. Вернуть обычную APK: `flutter build apk --debug --no-pub --dart-define=API_BASE_URL=http://10.0.2.2:3000/api/` и установить её.
