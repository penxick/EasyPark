# Cloudflare: диагностика авторизации — EasyPark 1.2.2+5

## Подтверждённая причина воспроизведённого сценария

Настройки ранее принимали и сохраняли домен без /api/. Проверка GET /health проходила, но AuthRepository добавлял относительный auth/login к корню, получая POST /auth/login. Backend принимает POST /api/auth/login. Аналогично ломалась регистрация. ApiConfig добавлял только завершающий слеш, но не API-префикс.

До: https://example.trycloudflare.com → POST https://example.trycloudflare.com/auth/login (404).
После: тот же ввод нормализуется в https://example.trycloudflare.com/api/ → POST https://example.trycloudflare.com/api/auth/login.

Адреса с /api и /api/ также поддерживаются. Дублированный /api/api и другие неподдерживаемые пути отклоняются до сохранения. Проверка подключения остаётся GET https://example.trycloudflare.com/health, только HTTP 200 и ожидаемый JSON. Старый сохранённый корневой адрес нормализуется и при восстановлении приложения. URL туннеля не захардкожен.

Важно: действующий Cloudflare URL и точный сохранённый адрес физического телефона не предоставлены. Поэтому описанный дефект подтверждён кодом, воспроизведением URL и локальными HTTP-запросами, но его совпадение с конкретным случаем телефона пока не подтверждено. Для уже корректного /api/ прежний код формировал правильные маршруты. Утверждать устранение любого другого источника 404 без фактического запроса с устройства нельзя.

## Проверка работающего backend

Без перезапуска Docker и без изменения данных выполнены реальные запросы к localhost:3000:
- GET /health → 200.
- POST /api/auth/login с {} → 400.
- POST /api/auth/register с {} → 400.
- POST /auth/login с {} → 404.

NestJS global prefix — api; GET health исключён из него. DTO входа принимает login/password; Flutter отправляет эти поля методом POST. Регистрация отправляет name/email/password, что соответствует DTO. Расхождения маршрутов работающего контейнера с исходниками не обнаружено; реальные корректные учётные данные не отправлялись. Docker не пересобирался, миграции не выполнялись.

## Актуальность клиента

AuthController при смене сервера закрывает прежний клиент и заменяет AuthRepository.api. Вход, регистрация и /users/me обращаются к нему. Router создаёт репозитории USER/ADMIN с auth.repository.api; фиксированных Cloudflare URL в сервисах нет. Проверка нового сервера выполняется без JWT. До успешной проверки сохранение и выход не выполняются.

Тест с реальными методами AuthRepository и подменённым HTTP-транспортом проверяет последовательность: локальный адрес → сохранение Cloudflare → POST login → POST register → GET parkings → восстановление контроллера → GET users/me → новый POST login. Все запросы идут к новому хосту; API-префикс ровно один.

## Диагностика и ошибки

В debug-сборке для auth/login и auth/register выводится одна строка EasyPark auth HTTP: метод, конечный origin/path без query, HTTP-статус, безопасная категория ошибки и elapsedMs. Тела, заголовки, пароли, email, JWT и текст исключений не выводятся. Режим отключается при сборке --dart-define=API_DIAGNOSTICS=false; в release не активен.

Распознаются HTTP-ошибки, timeout, TLS и известные сообщения DNS; прочие транспортные ошибки обозначаются network без предположений. TLS-проверка сертификатов не отключалась. HTTP 404 при авторизации объясняет несовместимый адрес API; 400 — некорректные поля, 401 — неверные учётные данные, 500 — ошибка сервера. Восстановление пароля и его ответы не менялись.

## Проверка на телефоне

1. Установить новый APK 1.2.2+5 поверх существующего приложения (не удалять данные).
2. На домашнем ПК оставить работающими backend и Cloudflare Tunnel.
3. Через шестерёнку указать текущий HTTPS-домен туннеля или полный адрес с /api/. Проверить подключение и сохранить.
4. Войти в существующий аккаунт. Открыть парковки. Перезапустить приложение и проверить восстановление подключения.
5. Через мобильный интернет создать тестовое бронирование обычным интерфейсом и проверить его в ADMIN на домашнем ПК.
6. Если ошибка остаётся, передать точный введённый URL и безопасную строку EasyPark auth HTTP из adb logcat. Не передавать полный logcat, пароль или JWT. Quick Tunnel URL после перезапуска туннеля может измениться.

Адрес APK по умолчанию http://10.0.2.2:3000/api/ предназначен для Android Emulator; на телефоне обязательно сохранить актуальный HTTPS URL.
