# EasyPark — тарифы, длительность и навигация

Дата: 12.10.2026.

## Реализация

- Существующая Parking расширена полем `pricePer30Min`: PostgreSQL `numeric(10,2)`, неотрицательное значение, по умолчанию 0. ADMIN задаёт тариф в существующей форме создания/редактирования. Старое поле `pricePerHour` сохранено для совместимости; новые бронирования рассчитываются по тарифу за 30 минут.
- API принимает десятичную строку (также совместим с числовым JSON-вводом), возвращает новый тариф строкой. Backend переводит тариф в целые копейки через BigInt, умножает на количество интервалов и сохраняет точную десятичную строку в существующий `totalPrice`. Числовой формат ответа `totalPrice` сохранён для совместимости. Старые бронирования не пересчитываются.
- Продолжительность: 30–180 минут, шаг 30, начальное значение 30. Сохранён существующий более строгий предел 180 минут, что допускает ТЗ. Добавлены 90 и 150 минут. Flutter считает предварительную сумму в целых копейках; итог после создания берётся из ответа backend.
- Существующие проверки доступности, физической занятости и бронирований сохранены.
- USER-карта получила кнопки масштаба ±1 с ограничениями 2–19, жесты сохранены. ADMIN-карта не получила лишних элементов управления.
- Местоположение запрашивается только по действию пользователя; отображается маркер и выполняется центрирование, включая повторное нажатие с теми же координатами. Добавлены разрешения Android/iOS, обработка отказа, отключённого GPS и таймаута.
- В карточке парковки добавлена кнопка маршрута. Используется автомобильный OSRM, линия на существующей карте, подбор масштаба, расстояние/время и скрытие маршрута. Ошибка сервиса не убирает карту. Координаты передаются маршрутизатору, о чём сообщает UI, но не EasyPark backend/БД. JWT маршрутизатору не отправляется.
- Добавлена необходимая библиотека geolocator; для HTTP используется существующая библиотека. Фоновое слежение, оплата и голосовая навигация отсутствуют.

## Миграция и запуск

Добавлена `backend/src/database/migrations/1791763200000-add-parking-price30.ts` (`AddParkingPrice301791763200000`), зарегистрирована в существующем DatabaseModule. Добавляет столбец с default 0 и CHECK; поддерживает down. Применена к локальной PostgreSQL. Пользователи и история бронирований не изменялись.

Для другого компьютера перед запуском нового backend:

```powershell
cd D:\EasyPark\backend
npm ci
npm run build
npm run migration:run
npm start
```

Использовать существующий `.env`. Для запуска контейнерной версии потребуется обновить образ backend обычной командой проекта; в рамках этих проверок обновлённый backend запускался локально на 3001, контейнер backend не пересобирался.

Flutter: `flutter pub get`, затем существующая команда запуска с `API_BASE_URL`. Новый debug APK предназначен для эмулятора с `http://10.0.2.2:3000/api/`. На физическом телефоне нужен доступный адрес backend.

Маршрутизатор по умолчанию: `https://router.project-osrm.org/route/v1/driving/`. Можно задать другой совместимый HTTPS endpoint через `--dart-define=ROUTING_BASE_URL=...` (полный префикс до координат). Публичный demo-сервис не гарантирует доступность, ключей и платной подписки нет. Таймаут 15 секунд. См. [OSRM HTTP API](https://project-osrm.org/docs/v26.6.1/http/) и [geolocator](https://pub.dev/packages/geolocator).

- Временные аккаунты, парковки, места и бронирования Android-проверки удалены штатным fixture cleanup.
- Дополнительный запуск Android-сценария без `TEST_GPS` остановлен: `flutter drive` несколько минут не выводил прогресс при доступном adb-эмуляторе и запущенном API. ### Исправление GPS после сравнения провайдеров

Диагностика `pricing-gps-providers.log` показала: Google Fused Location завершает запрос TimeoutException, а Android LocationManager возвращает правильную тестовую координату. В `ParkingNavigation.locate` добавлен резервный foreground-запрос LocationManager только для Android и только после TimeoutException основного запроса. Обе попытки ограничены 15 секундами (до 30 секунд суммарно). Проверки разрешений сохранены, фонового слежения и подстановки старых/фиктивных координат нет. iOS/web fallback не используют.

Добавлены два теста выбора fallback: Android выполняет второй запрос с `forceLocationManager: true`, iOS возвращает понятную ошибку без второго запроса. Все 6 тестов навигации прошли. Изолированный Android-тест **после исправления прошёл**, exit 0, около 21 секунды; проверены обе координаты с допуском 0,001 градуса. Лог `mobile/pricing-gps-fixed.log`. Разрешения по-прежнему выдавались тестовому APK через adb, а координаты — эмулятором; реальный телефон и нативный диалог разрешений этим не проверены.

Итоговый `flutter analyze --no-pub` — без замечаний. Полный Flutter-набор после исправления — **118 тестов прошли**. Первый запуск не смог создать временный файл на C: (errno 112, недостаточно места); повтор выполнен с TEMP/TMP в игнорируемой `D:\EasyPark\.artifacts\flutter-temp` и прошёл. Настройки окружения менялись только для проверочной команды, пользовательские файлы не удалялись. Контрольные суммы 75 исходных материалов и `git diff --check` проверены повторно без изменений/ошибок.

Обычная debug-сборка с исправлением GPS успешно собрана (21,2 секунды) и установлена на эмулятор. APK: `mobile/build/app/outputs/flutter-apk/app-debug.apk`, backend URL для эмулятора: `http://10.0.2.2:3000/api/`.
