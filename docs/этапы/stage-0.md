# Этап 0 — создание структуры

## Объём

Созданы самостоятельные проекты Flutter/Dart, NestJS/TypeScript, Python/FastAPI,
Docker Compose и PostgreSQL. Никакие сущности, JWT, TypeORM, ConfigModule,
ValidationPipe, маршрутизатор Flutter, UI-kit, API-клиент и CV-детекция не добавлены.
Они относятся к этапам 1 и далее. Health endpoints реализованы уже здесь,
поскольку этого прямо требует критерий готовности этапа 0.

Backend: `GET /health`, порт 3000, ответ `status=ok`, `service=easypark-backend`.
CV: `GET /health`, порт 8000, ответ `status=ok`, `service=easypark-cv`.
Оба endpoint — liveness. Подключение NestJS к БД будет на этапе 1.
PostgreSQL имеет отдельный healthcheck и постоянный Docker volume.
Flutter: минимальный экран EasyPark, сгенерированы Android и iOS host projects.

## Найденные и устранённые проблемы

1. Docker Desktop не был запущен — запущен.
2. Порты PostgreSQL 5432 и 5433 заняты существующими службами — внешний порт
   EasyPark изменён на 55432; внутри контейнера остаётся 5432. Чужие службы не менялись.
3. При первой Android-сборке произошёл TLS-сбой скачивания Kotlin/Gradle —
   штатный повтор Flutter успешно завершил сборку; проверка TLS не отключалась.
4. ESLint 9 выдавал предупреждение о прекращении поддержки — обновлён до ESLint 10,
   требования к Node.js уточнены, lint пройден.
5. Starlette предупреждал об устаревающем TestClient с httpx — тесты переведены на
   httpx ASGITransport, повтор с `-W error` прошёл без предупреждений.
6. Ограничения песочницы препятствовали кешам SDK, сети, Docker и дочернему
   процессу Node test runner — операции выполнены с разрешённым расширенным доступом.

## Особенность локального Android-эмулятора

Первый запуск headless Pixel 7 давал чёрные снимки; при холодном старте также
появлялось сообщение о зависании Android System UI. Визуальная проверка выполнена
после холодного запуска AVD с `-no-snapshot -gpu swiftshader_indirect` и
диагностического запуска приложения:

```powershell
flutter run -d emulator-5554 --debug --no-pub --enable-software-rendering --no-enable-impeller
```

Экран EasyPark отрисован и осмотрен: [снимок](../.artifacts/stage-0-android.png).
В коде и AndroidManifest отключение Impeller не закреплялось. Flutter предупреждает,
что диагностический флаг opt-out Impeller устаревает; он не нужен для обычной
сборки и не является настройкой проекта. Работа аппаратного рендеринга на физическом
Android-устройстве в этом этапе не проверялась.

По завершении проверки запущенный для теста эмулятор остановлен. Три контейнера
EasyPark оставлены запущенными. Для остановки используйте `docker compose down`.
