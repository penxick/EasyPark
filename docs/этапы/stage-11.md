# Этап 11 — Parking Layout

Выполнен этап 11. Этап 12 (Reservation Backend) не начат.

## Реализация

Из подробного экрана кнопка «Выбрать место» открывает `/parking/:id/spaces`.
Экран получает данные из `GET /api/parkings/:id/spaces` через общий JWT API-клиент.
Есть загрузка, повтор запроса, обновление, пустой список, обработка 404 и возврат.
Ответ 401 завершает сессию существующим механизмом авторизации.

Схема реализована Flutter widgets: цветные прямоугольники с кодами A01…D05,
легенда, счётчик свободных мест, перемещение, масштабирование и сброс масштаба.
Координаты берутся из API, число мест не зашито в интерфейс. Использованы цвета
и расположение демосхемы из Figma-прототипа; React-код и зависимости не переносились.
Статусы FREE, OCCUPIED, RESERVED, UNAVAILABLE отображаются зелёным, красным,
жёлтым и серым соответственно. FREE при physicalOccupied=true отображается
занятым и не выбирается. Неизвестный статус безопасно считается недоступным.

Нажатие свободного места выделяет его и показывает код выбранного места.
Это локальное выделение, не бронь. Обновление загружает актуальные данные и
сбрасывает выделение. Проверяются структура ответа, ID парковки, уникальность
кодов/ID и конечность неотрицательных координат. Для увеличенного системного
шрифта схема открывается крупнее; доступны прокрутка страницы и перемещение схемы.

## Границы

Нет создания брони, оплаты, realtime, CV-разметки polygon или административного
редактирования схемы. Схематический проезд иллюстрирует деморасположение мест,
а не дорожную навигацию. Краткая карточка карты пока не показывает числовую
доступность; её текст не менялся. iOS-сборка на Windows не проверялась.
Дальнейшая разработка — только по отдельной команде пользователя.
