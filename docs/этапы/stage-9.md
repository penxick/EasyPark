# Этап 9 — Parking Details

Выполнен экран информации о парковке. Этап 10 не начат.

## Результат и границы

«Подробнее» на карте открывает /parking/:id. Экран получает актуальный объект через
GET /api/parkings/:id с текущим JWT, показывает название, адрес, стоимость,
режим работы, описание и поля «Свободно» / «Всего». Есть обновление данных,
состояние загрузки, повтор при ошибке, отдельное сообщение 404 и обработка 401
общим контроллером авторизации. Возврат из подробностей сохраняет карту;
при прямом открытии маршрута кнопка «Назад» открывает главную страницу.
Смена id загружает новый объект; устаревшие ответы отсеивает LoadController.

Числа свободных и всех мест текущий API ещё не возвращает: ParkingSpace предусмотрен
этапом 10. Поэтому оба поля показывают «Нет данных», а не фиктивный ноль.
Модель принимает необязательные freeSpaces/totalSpaces: целые неотрицательные
числа, freeSpaces не больше totalSpaces. Нулевые значения отображаются как 0.
Это подготовка отображения; серверный расчёт счётчиков здесь не реализован.
Выбор места и бронирование не добавлялись.

Использованы существующие Flutter UI-компоненты, цвета и отступы Figma.
Изучены BookingDialog.tsx и ранее DriverApp.tsx: белые карточки, синие акценты,
иконки адреса/времени, парные показатели свободных и всех мест.
Оплата и выбор длительности из прототипа не переносились.
При малой ширине и крупном тексте показатели располагаются вертикально,
всё содержимое прокручивается. Новых зависимостей нет.
