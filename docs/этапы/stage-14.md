# Этап 14 — История

Реализованы категории бронирований. Этап 15 (Profile) не начат.

## Поведение

Экран «Бронирования» получает полный личный список через существующий
GET /api/reservations/me и показывает три категории:

| Категория | Статусы сервера |
|---|---|
| Активные | ACTIVE, PENDING |
| Завершённые | COMPLETED, EXPIRED |
| Отменённые | CANCELLED |

EXPIRED остаётся подписан «Срок истёк», а не «Завершено». Клиент не завершает
бронь по собственным часам: статус определяет backend. Порядок от новых к старым
сохраняется из API. Карточки содержат парковку, код места, статус, даты и стоимость.
В завершённых и отменённых карточках кнопки отмены нет.

После успешной отмены запись сразу исчезает из активных и появляется в отменённых
без повторного создания запроса. Подтверждённый ответ PATCH имеет приоритет над
ранее начатой загрузкой списка, поэтому устаревший ответ не возвращает активный статус.
При повторном открытии история загружается из сервера. Фильтры не отправляют
дополнительные запросы; выбранная категория сохраняется при обновлении.
У каждой категории отдельное пустое состояние. Есть загрузка, ошибка с повтором,
ручное обновление и существующее обновление при возврате к вкладке/приложению.

Использованы нативные Flutter ChoiceChip/Wrap в цветах существующей темы Figma:
на узких экранах категории переносятся, содержимое прокручивается. Исходный
DriverApp.tsx изучен как визуальный ориентир; в нём нет готового экрана трёх
категорий истории, поэтому категории определены ТЗ и оформлены в текущем UI-kit.
Web-код и зависимости не переносились.

- `dart format` — выполнено; `flutter analyze` — замечаний нет.
- `flutter test` — все 72 теста прошли.
- Проверены все пять статусов, отсутствие отмены у истории, сохранение категории
  после обновления и ошибки, мгновенный перенос отменённой записи, загрузка
  отменённой записи после пересоздания экрана, ширина 320 и текст ×2.

  Экран переведён на общий LoadController, который перехватывает ошибки и
  игнорирует устаревшие результаты. Повторный полный прогон прошёл.
- `flutter test tool/render_history_test.dart --dart-define=FLUTTER_SDK=C:/Users/User/flutter/flutter`
  — рендер всех трёх категорий при ширине 390 и 320 прошёл. Просмотрены активная,
  завершённая и отменённая категории; переполнений Flutter нет.
- Android API 36, реальный backend: расширенный reservation_flow_test.dart прошёл.
  Бронь создана, отменена, сразу исчезла из активных, появилась в отменённых
  и сохранилась там после обновления; проверено пустое состояние завершённых.
- Android использовал отдельные тестовые парковку, место и аккаунт. После проверки
  удалены только эти записи и связанные тестовые брони; эмулятор остановлен.
- Собран обычный debug APK после интеграционного теста и исправления загрузки.
